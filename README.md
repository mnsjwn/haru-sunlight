# 일광 처방

오늘 언제 몇 분 햇빛을 쬐야 비타민D가 채워지는지 계산해 주는 앱.
개발명세 §2~§4(공식 · 상수 · 분기 조건)를 **그대로** 구현했고, UI는 토스 스타일로 맞췄습니다.

- 백엔드 서버 없음 · 딥러닝 없음 · 매일 입력할 것 없음
- 날씨는 **기상청 API 2개**(단기예보 + 생활기상지수)만 쓴다. 하루 1회 호출, 나머지 계산은 전부 브라우저에서
- ✅ 실제 서비스키로 두 API·전체 파이프라인 라이브 검증 완료 (아래 "검증" 참고)

---

## 실행

```bash
cd sunlight-rx
python -m http.server 8765
# → http://127.0.0.1:8765
```

처음 열면 **"기상청 서비스키가 설정되지 않았어요"** 화면이 뜹니다. 아래대로 키를 넣어 주세요.

## 🔑 서비스키 설정 — 앱 기능이 아니라 파일 하나로만

**설정 화면에 입력란이 없습니다.** 의도적으로 뺐습니다. 키는 오직 로컬 파일로만 넣습니다.

```bash
cd sunlight-rx
copy config.local.example.js config.local.js     # (macOS/Linux는 cp)
```

`config.local.js`를 열어 한 줄만 채웁니다.

```js
window.KMA_SERVICE_KEY = '여기에_발급받은_서비스키';
```

저장하고 새로고침하면 바로 시작됩니다. 이 파일은 **`.gitignore`에 등록돼 있어 깃허브에 절대
올라가지 않습니다.** 커밋되는 건 빈 값이 든 `config.local.example.js` 템플릿뿐입니다.

- 키가 필요한 사람(테스트하는 본인)만 이 파일을 로컬에 만들어서 씁니다. 저장소를 받은
  다른 사람에게는 이 파일이 없으므로, 받자마자 키 없이 "설정에서 방법 보기" 화면부터 봅니다.
- 설정 화면에는 **읽기 전용 상태 카드**만 있습니다 — 키가 감지됐는지, 그리고 감지됐을 때만
  뜨는 "연결 확인" 버튼(진짜 데이터가 오는지 눌러서 테스트하는 용도, 입력 기능 아님).
- 키를 커밋 메시지·이슈·스크린샷·채팅에 붙여넣지 마세요. 검증 과정에서 실키를 한 번
  써야 했을 때도 레포 밖 임시 파일에서만 호출하고 즉시 삭제했습니다(레포 전체 grep으로 확인).

## 계층 구조

기능마다 **로직(백엔드 역할)** 과 **화면(프론트)** 을 파일로 분리했습니다.
`core/`와 `*.service.js`는 DOM을 전혀 건드리지 않으므로 그대로 서버(Node)로 옮길 수 있습니다.

```
core/                        ← 백엔드 계층 (순수 로직 · 데이터)
  solar.js                   1) 태양고도       — NOAA Solar Position Algorithm (+ 일출·일몰 이분탐색)
  engine.js                  2) 계산 엔진      — §2 공식 · §3 열 상한 · §4 모드 · §6 생체리듬 · 저장량
  kma.geo.js                 좌표 변환         — 위경도 → 단기예보 격자(nx,ny) · 생활기상지수 지점코드(areaNo)
  providers/kma.provider.js  1계층 외부 데이터 — 기상청 단기예보 + 생활기상지수 호출·파싱·병합
  weather.api.js             파사드            — 하루 1회 호출·캐시·폴백. 위 계층은 기상청인지도 모른다
  store.repo.js              저장소            — 설정 · 서비스키 · 노출 이력 · 예보 캐시 (localStorage)
  prescription.js            유스케이스        — 위를 조합해 "그날의 처방"을 만든다

features/<기능>/
  <기능>.service.js          그 기능의 로직 (뷰모델 생산 · DOM 접근 없음)
  <기능>.view.js             그 기능의 화면 (렌더 + 이벤트만)

  onboarding/                §7 온보딩 (1회, 약 30초)
  home/                      §9 홈 — 오늘의 처방
  timer/                     §9 노출 타이머
  weekly/                    §9 주간 충전률 · 이력
  settings/                  §9 설정

shared/
  ui.js                      포맷 · 아이콘 · 토스트 · 바텀시트
  chart.js                   시간별 UV·기온 그래프 (인라인 SVG)
  notify.js                  창 15분 전 알림
  app.js                     앱 셸 — 부트스트랩 · 탭 라우팅 · 상태 보유

css/style.css                토스 스타일 디자인 시스템
sw.js · manifest.json        PWA (오프라인 셸 캐시)
tests/                       스모크 테스트 · 스크린샷용 시드 페이지

config.local.example.js      서비스키 템플릿 (커밋됨, 값은 비어 있음)
config.local.js              실제 키 (⚠️ 각자 로컬에 직접 만든다 · .gitignore 등록됨 · 깃허브에 안 올라감)
```

데이터 흐름은 아키텍처 그림 그대로 한 방향입니다.

```
기상청 단기예보 ─┐
                  ├─(하루 1회)─▶ weather.api ─▶ prescription ─▶ <기능>.service ─▶ <기능>.view
기상청 생활기상지수 ┘                                ▲                                  │
                                                store.repo ◀───── 설정 변경 시 재계산 ──┘
```

지역 선택은 이미 두 경로 다 됩니다 — 온보딩/설정에서 도시 18곳 중 클릭하거나, GPS로 현재 위치를 잡으면
그 좌표로 격자(nx,ny)·지점코드(areaNo)를 바꿔 계산해 완전히 다른 날씨·모드가 나옵니다.

## §1 통일 대상 — 명세 그대로 구현한 값

| 항목 | 값 | 위치 |
|---|---|---|
| `k` | **0.4** | `core/engine.js` |
| UVI 환산계수 | **1.5** (고정) | 〃 |
| MED | I 150 · II 250 · **III 300(기본)** · IV 400 · V 500 · VI 600 J/m² | 〃 |
| f_BSA | 반팔반바지 0.40 · 반팔긴바지 0.25 · 긴팔긴바지 0.10 | 〃 |
| SPF | 안 바르면 1 | 〃 |
| 창 조건 | 고도 ≥ 45° · 열 상한 > 0 · 노출시간 ≤ 60분 (셋 다) | `Engine.isOpen` |
| 열 상한 | ~31℃ 무제한 · 31~35 20분 · 35~38 10분 · 38~ 0분 | `Engine.heatCap` |
| 모드 순서 | 겨울 → 폭염 → 장마·흐림 → 평상 (첫 히트 적용) | `Engine.decideMode` |
| 반감기 | 25(OH)D 21일 | `Engine.HALF_LIFE_DAYS` |

노출시간 → IU 환산은 **하지 않습니다**(§10). 충전률 %로만 표시합니다.

`tests/smoke.html` — 브라우저에서 열면 52개 검사가 자동 실행됩니다.
헤드리스로 돌리려면:

```bash

chrome --headless=new --virtual-time-budget=20000 --dump-dom \
  http://127.0.0.1:8765/tests/smoke.html
```

현재 **70 PASS / 0 FAIL**. 검사 범위:

- §3 체감온도 구간 경계 4개 + NOAA Heat Index 값
- 태양고도: 서울 하지 75.87°(이론 75.9) · 동지 28.99°(이론 29.0)
- §4 모드 판정 우선순위 4가지, 폭염 모드의 오전 창 필터링
- 창 열림 3조건 각각의 경계
- 충전률 · 반감기 감가 · 연속 미노출일
- §6 생체리듬 Tmin / 빛 회피 창 / 위상 방향
- 기상청 좌표 변환(nx,ny) 8개 도시 · 국내/국외 판정

- 모의 데이터로 처방 파이프라인 전 구간(타이머·주간·설정까지)

## ⚠️ 명세에서 확인이 필요한 지점

구현하면서 실제 숫자로 드러난 것들입니다. **임의로 바꾸지 않고 명세대로 두었습니다.**

### 1. `f_BSA`가 분자에 있어 방향이 뒤집힙니다 — 가장 시급

§2 공식 `(k × MED × f_BSA) ÷ (1.5 × UVI)`에서 f_BSA가 분자라, **옷을 더 입을수록 필요시간이 짧아집니다.**

| 옷차림 | f_BSA | 필요시간 (UVI 8, 피부 III) |
|---|---|---|
| 반팔 + 반바지 | 0.40 | 4.0분 |
| 긴팔 + 긴바지 | 0.10 | **1.0분** ← 더 짧음 |

선량 = 조사강도 × 시간 × 노출면적이므로 물리적으로는 분모가 맞습니다.
`core/engine.js`의 `F_BSA_IN_DENOMINATOR`를 `true`로 바꾸면 뒤집힙니다(기본 `false` = 명세 그대로).
§1이 "공식은 반드시 통일"이라고 못박아서 조 결정 전에는 건드리지 않았습니다.

### 2. 화상 한계선은 구조적으로 절대 걸리지 않습니다

`화상 ÷ 비타민D = SPF ÷ (k × f_BSA)` = 차단제를 안 발라도 **6.25배**.
차단제를 바르면 더 벌어집니다. 즉 `limitedBy === 'burn'`은 발생할 수 없고,
홈의 세 제약 중 화상 카드는 항상 여유 상태로만 표시됩니다.
"왜 화상은 한 번도 결정자가 안 되나요?"는 발표에서 나올 만한 질문입니다.

### 3. SPF가 비타민D 식에는 없습니다

§2는 SPF를 화상 식에만 넣습니다. 그래서 **선크림을 발라도 비타민D 필요시간은 그대로**입니다.
실제로는 차단제가 UVB를 막아 합성도 함께 느려집니다.

### 4. 폭염이 장마보다 우선순위라 장마철에 '폭염 모드'가 뜹니다

§4 순서상 체감온도 31℃가 먼저 걸립니다. 27℃ · 습도 90%면 체감 31℃라
비 오는 날에도 "폭염 모드 · 오전 창만"으로 판정됩니다. 순서를 바꿀지, 라벨만 손볼지 결정이 필요합니다.

### 5. 기상청 2개 API로 전환하면서 생긴 것

Open-Meteo(팀 공용 `weather.js`)는 완전히 뺐습니다. 이제 날씨는 **기상청 단기예보 + 생활기상지수**
두 API만 씁니다(`core/providers/kma.provider.js`). 실키로 라이브 검증까지 마쳤습니다(위 "검증" 참고).

**국내 전용입니다** — 기상청 API가 해외 좌표를 지원하지 않습니다. GPS가 국외 좌표를 주면
명시적으로 거부하고 도시 선택으로 안내합니다(`WeatherAPI.locate()`). 이 때문에 **겨울 모드를
지금(여름) 데모로 보여줄 방법이 없어졌습니다** — 예전엔 남반구 도시(퀸즈타운)로 우회했지만
이제 국내로 막혀 있어서, 실제 겨울철에만 재현됩니다.

**열 안전 상한은 §3의 NOAA Heat Index 그대로입니다** — 기상청 단기예보는 체감온도를 안 주고
기온(TMP)·습도(REH)만 줍니다. Open-Meteo 시절엔 예보가 주는 체감온도를 우선 썼지만,
기상청에선 그 필드 자체가 없어서 `Engine.heatIndex()`가 항상 §3 공식으로 계산합니다.
**결과적으로 §1 "공식 통일"에 더 가까워졌습니다** — 팀 전체가 같은 §3 공식을 쓰게 됩니다.

**구름 손실(cloudLoss)은 뺐습니다** — 기상청 생활기상지수는 청천 UV(구름 없었다면의 값)를
주지 않아서 "구름이 몇 % 깎았는지" 계산이 불가능합니다. 대신 흐림 안내에는 실측 UV 수치
자체("오늘 최고 자외선지수가 0.4로 낮아…")만 넣었습니다.

**일출·일몰은 직접 계산합니다** — 기상청 단기예보에 없는 항목이라 `Solar.sunriseSunset()`을
새로 추가했습니다(고도 -0.833°를 지나는 시각을 이분탐색). NOAA SPA와 같은 엔진이라 정확도는
동일합니다. 라이브 검증에서 서울 8/31 일출 06:01/일몰 19:03로 나왔고, 이는 §3 검증 때 쓴
NOAA 이론치와 일치합니다.

**예보 기간**은 확인 결과 하루가 아니라 **당일 포함 4일치**가 옵니다(단기예보 발표 시각에
따라 3~4일로 조금씩 달라질 수 있습니다). 주간 화면의 "앞으로 N일"이 실제 도착한 일수만큼
자동으로 늘어납니다.

**areaNo(생활기상지수 지점코드)는 서울만 실키로 확인**했습니다(`1100000000` 정상 응답).
나머지 17개 도시는 행정표준코드 형식대로 채워 넣었지만 실호출로 대조하지 못했습니다.
설정 → "연결 확인"으로 도시를 바꿔 가며 한 번씩 눌러 보면 바로 걸러집니다
(UV만 실패하면 날씨는 살리고 `uvMissing: true`로 표시하도록 이미 만들어 뒀습니다).

**출처 표기**는 홈 하단에 "기상 데이터 기상청 단기예보 · 생활기상지수"로 바꿨습니다.
공공데이터포털 이용약관에 구체적인 표기 의무 조항이 있는지는 별도 확인이 필요합니다
(Open-Meteo의 CC BY 4.0처럼 명문화된 문구를 보진 못했지만, 확정된 건 아닙니다).

Open-Meteo 시절엔 ES 모듈 때문에 더블클릭(`file://`)이 원천 차단됐는데, 지금은 전부 classic
스크립트라 그 제약은 없어졌습니다. 다만 `file://`에서는 브라우저마다 위치 권한·`fetch` CORS
처리가 달라 안정적이지 않으므로, 여전히 `python -m http.server`를 권장합니다.

### 6. 명세 §10 미결정 항목 처리 방식

- **`k` = 0.4** 중앙값 그대로. 홈 → "계산 근거 보기"에 문헌 편차를 명시해 뒀습니다.
- **생체리듬 축은 포함**했습니다(아키텍처 2계층에 있어서). 온보딩 질문은 2개 + 위치.
- **IU 미표시**, 충전률 %로만.
- **식이 대체는 식품명만** 표기하고 IU 수치는 넣지 않았습니다(§10에서 미확정).
  용량 지시는 하지 않고, 공식 기준(충분섭취량 400 IU/일 · 상한 4,000 IU/일,
  한국인 영양소 섭취기준 2020)만 그대로 인용합니다.
- **조건 기반 영양소 모듈**은 근거가 없어 넣지 않았습니다.

## 그 외 구현 메모

- '지금'은 기기 시계가 아니라 **예보 지점의 현지 시각**으로 계산합니다(다른 시간대 조회 대비).
- 타이머는 단순 카운트다운이 아니라 **누적 선량** 방식입니다. 매 초 `dt ÷ 그 순간의 필요시간`만큼
  채워지므로, 도중에 옷을 걷거나 구름이 껴도 남은 시간이 즉시 다시 계산됩니다.
- 예보는 하루 1회만 받고 localStorage에 캐시합니다. 네트워크가 끊기면 옛 캐시로 계산하고
  홈 상단에 그 사실을 표시합니다(발표 중 네트워크 사고 대비).
- 창이 하나도 없는 날 "오늘은 무리"라고 말하는 것도 기능으로 넣었습니다(§9).
